02

GitHub Issues

Una actividad debe describirse suficientemente

Un Issue relevante debe procurar incluir título claro, referencia WBS, descripción, responsable, criterio para considerarlo terminado, Sprint, etiquetas útiles y evidencia/comentarios.

[WBS 2.3] Implementar generador PWM Responsible: María Done when: código integrado + revisión + evidencia

Idea operativa

Evite Issues vagos

“Hacer PWM” no permite entender alcance, responsabilidad ni criterio de terminado.

03

Project Board

El tablero debe reflejar el estado real

El seguimiento cotidiano puede organizarse mediante Backlog → To Do → In Progress → Review → Done, incorporando Blocked cuando una dependencia, recurso, decisión, falla o restricción impide continuar.

Idea operativa

main representa estabilidad

Después de establecer la Design Baseline, el desarrollo no debe realizarse directamente sobre main. Los cambios se integran mediante ramas y Pull Requests.
