01

Documentos vivos

Sprint I no se archiva y se olvida

Durante Sprint II deben actualizarse cuando sea necesario la WBS, RACI, Risk Register y Project Schedule. El Project Charter se modifica sólo ante cambios fundamentales.

Idea operativa

Control de versiones documental

Use nombres consistentes como Risk_Register_v1.1.xlsx o Project_Schedule_v1.2.xlsx; el historial de Git complementa estas versiones.

03

Doble evidencia

Documento formal + historial real

La revisión no debe depender sólo de un informe. La misma historia debe poder observarse en Issues, ramas, commits, Pull Requests, archivos, versiones y el tablero de seguimiento.

Idea operativa

Versión opcional de revisión

Al finalizar puede establecerse sprint-2-review-v1.0 para identificar el estado revisado del proyecto.
