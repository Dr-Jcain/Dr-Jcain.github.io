4.4 · Laboratorio Abierto: Construcción

Cerrar con un repositorio que cuente la historia completa

El criterio final no es que el repositorio se vea ordenado, sino que permita reconstruir decisiones, responsabilidades, cambios, evidencia y el estado real de la solución.

01

Reglas generales

El repositorio debe sostener la trazabilidad

Un repositorio principal, cuentas individuales, main como estado integrado, Issues vinculados cuando sea posible con WBS, branches para desarrollar, Pull Requests para integrar, commits concretos, Project actualizado, documentos vivos y versiones identificables por Sprint.

Idea operativa

Evite versiones ambiguas

NO: final_final_ahora_si.xlsx SÍ: Risk_Register_v1.1.xlsx SÍ: Project_Schedule_v1.2.xlsx
02

Definición de Done

Terminado depende de la naturaleza de la tarea

Tipo de actividadEvidencia posible para Done
DocumentoArchivo generado + revisión + versión.
SoftwareCódigo integrado + PR aprobado + verificación.
HardwareDispositivo ensamblado + evidencia/revisión.
IntegraciónPrueba o verificación de funcionamiento.
GestiónDocumento/tablero actualizado y coherente.
03

Principios de cierre

Diez reglas resumen la forma de trabajo

Planear antes de ejecutar; asignar responsabilidades; mantener trazabilidad; usar control de versiones desde el inicio; documentar conforme ocurre; no ocultar desviaciones/problemas/pendientes; distinguir plan y estado real; justificar cambios; mantener evidencia individual y colectiva; entregar una solución comprensible y continuable.

Idea operativa
